## Администратор: от общей картины к заказу

![Статистика администратора: показатели выдачи, график, блюда и классы](docs/screenshots/admin-day.png)

Карточки показателей, столбцы графика, блюда и классы открывают связанные заказы. Доступны день и неделя, поиск, фильтры по статусу, блюду и классу, сортировка и пагинация. Открытые данные обновляются каждые 15 секунд и при возвращении в окно.

Блоки плавно появляются при открытии страницы и прокрутке, графики заполняются по очереди, кнопки и карточки реагируют на действия. Системная настройка уменьшенного движения отключает анимации. Пример с кнопкой повтора — на странице компонентов.

## Повар: добавить, приготовить, отметить готовность

![Кабинет повара: заказы на сегодня и действия приготовления](docs/screenshots/cook.png)

Повар вручную вводит название блюда и класс или группу, указывает число порций, дату и время подачи. Новые названия сохраняются автоматически и появляются в фильтрах и аналитике. **Новый → Готовится → Готово.** Только статус «Готово» включает порции в выдачу. Повторное подтверждение не увеличивает показатели.

## Быстрый запуск

Нужен запущенный Docker с Docker Compose v2+. Для разработки без контейнеров приложений — Node.js 24.

```bash
git clone https://github.com/Hqzdev/stolovaya.git
cd stolovaya
cp .env.example .env
```

Заполните `.env`: два логина, два пароля не короче 8 символов и случайный `SESSION_SECRET` не короче 32 символов. Для генерации секрета: `openssl rand -hex 32`. Настройте пароль PostgreSQL и такую же строку подключения в `DATABASE_URL`.

```bash
docker compose up -d --build --wait
docker compose exec api npm run db:catalog
```

Откройте **[localhost:3000](http://localhost:3000)** и войдите одним из аккаунтов из `.env`. Миграции применяются автоматически. Команда `db:catalog` добавляет три блюда и четыре класса из макетов; существующие записи сохраняются.

## Рабочие и демонстрационные данные

По умолчанию открыт рабочий режим: пустые заказы и нулевая статистика. В кабинете администратора откройте **Настройки → Демонстрационные данные → Включить демо**. Режим общий для администратора и повара; открытые кабинеты обновляются в течение 15 секунд.

![Настройки: переключение рабочих и демонстрационных данных](docs/screenshots/settings.png)

В демо можно создавать заказы и менять статусы: они попадают только в демонстрационную статистику. Возврат к рабочим данным сохраняет оба набора. Общий справочник блюд и классов доступен в обоих режимах. При первом включении демо готовится автоматически; его дата используется как «сегодня», поэтому весь сценарий доступен и позже.

Необязательная предварительная загрузка демо через команду:

```bash
docker compose exec api npm run db:demo
```

Можно задать дату явно: `docker compose exec -e DEMO_DATE=2026-10-20 api npm run db:demo`. Команда заполняет только пустой демонстрационный набор и не переключает режим. Рабочие заказы сохраняются.

## Ровно две учётные записи

| Роль          | Логин         | Пароль           | Доступ                                |
| ------------- | ------------- | ---------------- | ------------------------------------- |
| Администратор | `ADMIN_LOGIN` | `ADMIN_PASSWORD` | Статистика, история, режим данных     |
| Повар         | `COOK_LOGIN`  | `COOK_PASSWORD`  | Создание заказов и изменение статусов |

Значения хранятся в `.env` на сервере. Регистрации, создания других аккаунтов и переключателя роли нет. Сессия живёт 8 часов; при смене учётных данных и перезапуске API прежние сессии этой роли перестают действовать. Настоящий `.env` исключён из Git.

## Стек и устройство

```mermaid
flowchart LR
    C[Повар] --> W[Next.js · интерфейс]
    A[Администратор] --> W
    W -->|/api/v1 · cookie + CSRF| N[NestJS · Node.js]
    N --> P[(PostgreSQL 18)]
```

| Слой      | Реализация                                                      |
| --------- | --------------------------------------------------------------- |
| Интерфейс | Next.js 16, React, TypeScript, Tailwind CSS 4, локальный Inter  |
| Сервер    | NestJS 12, Node.js 24, валидация DTO, OpenAPI                   |
| Данные    | PostgreSQL 18, `pg`, SQL-миграции, транзакции                   |
| Доступ    | Два аккаунта из окружения, HttpOnly-cookie, CSRF, проверка роли |
| Запуск    | Docker Compose: web + api + database, постоянный том            |

На сервере контроллеры принимают запросы, сервисы выполняют правила, репозитории обращаются к БД. Общие TypeScript-интерфейсы лежат в `packages/contracts`. Порции хранятся в заказах; агрегаты вычисляются SQL-запросами.

## Разработка и проверки

```bash
npm ci
docker compose up -d database
npm run db:catalog
npm run dev
```

Если приложение уже запущено целиком в Docker, сначала освободите порт: `docker compose stop web api`.

```bash
npm run lint
npm run typecheck
npm run build
npm run verify
```

Проверка API создаёт один заказ на 3 порции и удаляет его после проверки. Используйте отдельную локальную базу. `VERIFY_DEMO=true npm run verify` дополнительно проверяет контрольные значения демонстрационного набора. `npm run verify:data-modes` проверяет переключение, изоляцию и сохранность наборов. Браузерные сценарии и воспроизведение скриншотов описаны в [инструкции запуска](docs/SETUP.md#проверки-и-скриншоты).
