# API

Базовый путь: `/api/v1`. Интерактивная спецификация: [localhost:3000/api/v1/docs](http://localhost:3000/api/v1/docs). JSON OpenAPI: `/api/v1/docs-json`.

## Доступ

`POST /auth/login` принимает `{ "login": "…", "password": "…" }`. Сервер устанавливает HttpOnly-cookie и возвращает `{ user, csrfToken, today, timezone, workspace }`. Роль определяется аккаунтом из `.env`.

Все изменяющие запросы требуют `Origin`, совпадающий с `APP_ORIGIN`. После входа дополнительно нужен `X-CSRF-Token` из ответа входа или `/auth/me`. Cookie отправляется браузером автоматически. Сессию и CSRF не следует сохранять в localStorage.

Создание заказа и смена статуса также требуют `X-Data-Version`, равный `workspace.version` из `/auth/me`. Для чтения заказов и аналитики заголовок необязателен, но устаревшая переданная версия возвращает 409. Ответы содержат `X-Data-Version`. Это защищает от записи в другой набор после смены режима в соседней вкладке.

| Метод и путь                | Роль          | Назначение                                                  |
| --------------------------- | ------------- | ----------------------------------------------------------- |
| `GET /health`               | Все           | Проверка подключения к БД                                   |
| `POST /auth/login`          | Все           | Вход                                                        |
| `GET /auth/me`              | Обе           | Текущий аккаунт, дата, CSRF                                 |
| `POST /auth/logout`         | Обе           | Отзыв сессии, ответ 204                                     |
| `GET /settings`             | Администратор | Режим, версия, дата демо и количество заказов обоих наборов |
| `PATCH /settings/data-mode` | Администратор | Переключить режим для обеих ролей                           |
| `GET /catalog`              | Обе           | Блюда и классы                                              |
| `GET /orders`               | Обе           | Заказы и агрегаты по фильтрам                               |
| `GET /orders/:id`           | Обе           | Заказ и история событий                                     |
| `POST /orders`              | Повар         | Создать заказ, ответ 201                                    |
| `PATCH /orders/:id/status`  | Повар         | Начать приготовление или подтвердить готовность             |
| `GET /analytics`            | Администратор | Показатели, график, классы, блюда, последние заказы         |

| `GET /analytics/groups/:id` | Администратор | Аналитика класса и связанные заказы                         |

## Режим данных

`workspace` содержит `mode` (`live` или `demo`), `version`, `demoDate` и `today`. `PATCH /settings/data-mode` принимает `{ "mode": "demo", "version": 1 }`, где версия получена из настроек. Устаревшая версия возвращает 409. Повтор выбранного режима не меняет версию. Первый переход в демо заполняет отдельный набор, последующие сохраняют сделанные изменения. Повар не имеет доступа к чтению или изменению настроек.

Списки, подробности, история, создание и изменение заказов и вся аналитика работают только с активным набором. Номер заказа другого набора возвращает 404. Справочники общие. В демо `today` равен дате набора, в рабочем режиме — текущей дате столовой.

## Создание и статус

```json
{
  "dishId": "soup",
  "groupId": "9a",
  "quantity": 32,
  "serviceDate": "2026-10-20",
  "servingTime": "12:10"
}
```

Идентификаторы должны существовать в справочниках. Статус при создании всегда `new`. Смена: `{ "status": "cooking" }`, затем `{ "status": "ready" }`. Повтор того же статуса не меняет время и не добавляет событие. Пропущенный или обратный переход возвращает 409.

## Параметры списка

| Параметр        | Значение                                                                |
| --------------- | ----------------------------------------------------------------------- |
| `date`          | Дата `YYYY-MM-DD`, по умолчанию текущая дата столовой                   |
| `period`        | `day` или `week`; неделя заканчивается выбранной датой                  |
| `dish`, `group` | Идентификаторы справочников                                             |
| `status`        | `all`, `new`, `cooking`, `ready`, `pending`                             |
| `q`             | Поиск по блюду, классу и номеру заказа; до 100 символов                 |
| `hour`          | Локальный час готовности `00`–`23`, только готовые заказы               |
| `on`            | Конкретная дата внутри выбранного периода                               |
| `sort`          | `qty` по убыванию, `qty-asc` по возрастанию                             |
| `page`          | От 1; по 10 записей, выход за диапазон прижимается к последней странице |

`pending` объединяет новые и готовящиеся заказы. Ответ списка содержит `items`, `total`, `page`, `pageSize`, `totals`, `counts`, `scope`. `totals` соответствует всем выбранным фильтрам; `counts` для вкладок статусов соответствует всему временному периоду.

Общая аналитика принимает `date`, `period` и фильтры `dish`, `group`. Подробности блюда/класса фиксируют свою сущность и поддерживают пагинацию связанных заказов. Все интерфейсы ответов описаны в OpenAPI и `packages/contracts`.

## Ошибки

```json
{
  "statusCode": 400,
  "message": "Проверьте заполнение полей и выбранные фильтры."
}
```

400 — неверные данные; 401 — нет действующей сессии; 403 — запрещённая роль, origin или CSRF; 404 — запись не найдена; 409 — недопустимый переход; 429 — ограничение запросов; 500/503 — временная ошибка сервиса. Интерфейс показывает сообщение на русском и сохраняет заполненную форму при ошибке отправки.
