# Запуск и настройка

## Через Docker Compose

1. Запустите Docker Desktop или OrbStack.
2. Скопируйте `.env.example` в `.env` и заполните секреты. Ограничьте права: `chmod 600 .env`.
3. Выполните `docker compose up -d --build --wait`.
4. Выполните `docker compose exec api npm run db:catalog` для начальных блюд и классов.
5. Откройте `http://localhost:3000`.

Compose запускает три сервиса: `web`, `api`, `database`. Сервер применяет SQL-миграции перед началом работы. PostgreSQL использует постоянный том `postgres-data`; обычный `docker compose down` его сохраняет. Не используйте `down -v`, если нужны данные.

В начальном справочнике: куриный суп с лапшой, котлета с гречкой, творожная запеканка; классы 9А, 10Б, 8В и 7А. Заказы после обычного запуска отсутствуют.

## Окружение

| Переменная                                          | Назначение                                                                 |
| --------------------------------------------------- | -------------------------------------------------------------------------- |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD`                     | Единственная учётная запись администратора                                 |
| `COOK_LOGIN`, `COOK_PASSWORD`                       | Единственная учётная запись повара                                         |
| `SESSION_SECRET`                                    | Случайная строка от 32 символов для версий учётных данных                  |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Параметры контейнера PostgreSQL                                            |
| `DATABASE_URL`                                      | Подключение к PostgreSQL для разработки и локальных команд                 |
| `APP_ORIGIN`                                        | Разрешённый адрес интерфейса, по умолчанию `http://localhost:3000`         |
| `INTERNAL_API_URL`                                  | Адрес NestJS для Next.js; в Compose задаётся автоматически                 |
| `API_PORT`                                          | Порт сервера при разработке, по умолчанию 4000; внутри Compose всегда 4000 |
| `APP_TIMEZONE`                                      | Часовой пояс столовой, по умолчанию `Asia/Yekaterinburg`                   |
| `COOKIE_SECURE`                                     | `false` для локального HTTP, `true` для HTTPS                              |

Логины должны различаться, пароли — содержать от 8 до 256 символов, логины — до 100 символов. Настройка отсутствующих или одинаковых логинов останавливает сервер. Используйте `openssl rand -hex 32` для секрета и случайные пароли. Спецсимволы в `DATABASE_URL` кодируются по правилам URL; для простого локального пароля удобно использовать случайную шестнадцатеричную строку.

Docker формирует внутреннее подключение к `database:5432` из параметров `POSTGRES_*`. Локальный `DATABASE_URL` должен содержать тот же пароль и `localhost:5432`. Параметры `POSTGRES_*` инициализируют **новый** том. Изменение `.env` само по себе не меняет пароль уже созданного пользователя PostgreSQL: выполните `ALTER ROLE` в базе и согласованно обновите окружение.

После изменения логинов, паролей или `SESSION_SECRET`:

```bash
docker compose up -d --force-recreate api
```

Пароль предыдущей конфигурации больше не принимается. Старые сессии изменённой роли отзываются при следующем запросе. Регистрации и команды создания пользователей нет.

## Демонстрационные данные

```bash
docker compose exec api npm run db:demo
```

Команда загружает справочники и 44 заказа на семь дней, заканчивающихся текущей датой столовой. День: 174 из 246 порций; неделя: 994 из 1164. Два дня внутри набора пустые — это пример состояния без заказов.

Задать дату:

```bash
docker compose exec -e DEMO_DATE=2026-10-20 api npm run db:demo
```

В непустую базу заказов seed не записывает ничего. Начальное заполнение справочников можно повторять. Для нового демонстрационного стенда создайте отдельный Compose-проект с отдельным томом и свободными портами.

Справочники в версии 1.0 обслуживаются командами и SQL. Их можно дополнить параметризованным импортом в `dishes` и `school_groups` через административный клиент PostgreSQL; встроенных экранов редактирования справочников нет.

## Разработка

Нужен Node.js 24. Команды выполняются из корня репозитория:

```bash
npm ci
docker compose stop web api
docker compose up -d database
npm run db:migrate
npm run db:catalog
npm run dev
```

Next.js работает на 3000, NestJS — на 4000. Оба процесса автоматически перезапускаются при изменении исходников. `.env` читается сервером из корня проекта. Интерфейс обращается к `/api/v1`; Next.js передаёт запросы внутреннему API без размещения секретов в браузере.

Сборка: `npm run build`. Запуск собранных процессов: `npm run start -w @stolovaya/api` и `npm run start -w @stolovaya/web` в двух терминалах. Для локальной предсказуемой сборки используется Webpack.

## Проверки и скриншоты

```bash
npm run lint
npm run typecheck
npm run build
npm run verify
```

`verify` обращается к запущенному интерфейсу и напрямую к локальной БД только для удаления созданного проверкой заказа. Нужны `.env` и заполненные справочники. Для проверки контрольных чисел чистого демо: `VERIFY_DEMO=true npm run verify`.

Для браузерных сценариев и проверки смены учётных данных:

```bash
npx playwright install chromium
npm run verify:browser
npm run verify:credentials
npm run screenshots
npm run readme:assets
```

Если используется установленный Chrome, задайте `BROWSER_CHANNEL=chrome`. Скриншоты записываются в `docs/screenshots`; график README экспортируется из API в `assets/readme` вместе с исходными числами. Для фиксированного демо передайте одинаковый `DEMO_DATE` при seed и при экспорте.

Проверки создают временный заказ и удаляют его в `finally`. При принудительном завершении процесса проверьте оставшиеся заказы. Используйте отдельную базу без реальных записей. Браузерные проверки переходов и скриншоты рассчитаны на демонстрационный набор.

## Состояние и резервная копия

```bash
docker compose ps
docker compose logs --tail=50 api web
curl http://localhost:3000/api/v1/health
docker compose exec -T database sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

`health` проверяет доступность PostgreSQL. Дамп содержит заказы и сессии: храните его вне публичного репозитория. Для восстановления используйте отдельную пустую базу и `psql`; после восстановления отзовите прежние сессии сменой `SESSION_SECRET`.

## Частые проблемы

- **Docker недоступен:** запустите Docker Desktop или OrbStack.
- **Порт 3000 занят:** остановите предыдущий Next.js или контейнер `web`.
- **Нет блюд или классов:** выполните `db:catalog`.
- **Пустой кабинет повара после seed с фиксированной датой:** повар видит текущую дату столовой. Исторические данные доступны в аналитике администратора.
- **Неверный логин после изменения `.env`:** пересоздайте API-контейнер, убедитесь, что открываете нужный экземпляр приложения.
- **База не подключается:** сопоставьте пароль в `DATABASE_URL` с действующим паролем PostgreSQL; изменение `POSTGRES_PASSWORD` не переинициализирует существующий том.
