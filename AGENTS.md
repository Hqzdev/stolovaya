# Работа с проектом

## Стандарты кода

- Строго соблюдать ООП: одна ответственность, инкапсуляция, композиция вместо наследования.
- Писать минимальный, понятный и намеренный код. Без мёртвого кода и незавершённых заглушек.
- В React использовать композицию компонентов; бизнес-логику и HTTP-клиент отделять от отображения.
- На сервере: контроллер → сервис → репозиторий. SQL только в репозиториях и модуле БД.

## Инварианты

- Ровно два аккаунта, только из `.env`. Не добавлять регистрацию или CRUD пользователей.
- Только повар создаёт заказы и меняет их статус. Только администратор получает административную аналитику.
- Порции учитываются в выдаче при `ready`. Повторный статус не создаёт новое событие.
- Дата заказа задаёт период статистики; неделя заканчивается выбранной датой и включает семь дней.
- Секреты не выводить в логи, скриншоты, клиентские переменные или Git.

## Структура и команды

- `apps/web` — Next.js; `apps/api` — NestJS; `packages/contracts` — интерфейсы ответов.
- `npm ci`, `npm run dev`, `npm run lint`, `npm run typecheck`, `npm run build`.
- Проверки, если задача их требует: `npm run verify`, `npm run verify:browser`.
- SQL-миграции добавлять новым файлом; применённые миграции не переписывать.
- Демонстрационный seed запускается явно и только для пустой базы заказов.

## Внешний вид

Источник — `verify.pen` и страница компонентов. Фон `#f6f5f4`, белые поверхности, текст `#111111`, синий `#0075de`, жёлтый акцент `#ffb110`. Inter, тонкие границы, радиус карточек 12 px и кнопок 8 px. Без теней и градиентов. Текст интерфейса и документация на русском.
